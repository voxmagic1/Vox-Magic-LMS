## Outcome
Build failed at step `build_image` (Cloud Build). **Source-code fix required — NOT applied by the deployer.**

## What the committed error pointed at (red herring)
The `failed_step` excerpt surfaced the tail of Cloud Build **Step #0 "restore-pip-cache"**:
```
CommandException: No URLs matched: gs://emergent-default-customers-code/cache/damichromes-vocal/pip-cache.tar.gz
```
This is a **benign first-build cache miss** (no pip cache exists yet for a brand-new deployment). It is NOT the cause of the failure — it only appears in the tail. The gsutil miss does not stop the pipeline; the build proceeds.

## Actual root cause (Cloud Build Step #2 "docker-build", `RUN yarn build`)
The Next.js production build failed during static prerendering:
```
⨯ useSearchParams() should be wrapped in a suspense boundary at page "/payment/callback".
   Read more: https://nextjs.org/docs/messages/missing-suspense-with-csr-bailout
Error occurred prerendering page "/payment/callback".
Export encountered an error on /payment/callback/page: /payment/callback, exiting the build.
⨯ Next.js build worker exited with code: 1 and signal: null
error Command failed with exit code 1.
executor failed running [/bin/sh -c yarn build]: exit code: 1
```

Template: `nextjs_mongo_shadcn_base_image` (Next.js App Router). During `next build`, Next.js statically prerenders pages. A client hook `useSearchParams()` used at the page level forces client-side-rendering bailout, which the App Router **requires** to be wrapped in a `<Suspense>` boundary. Because `/app/payment/callback/page.(tsx|jsx)` calls `useSearchParams()` without such a boundary, prerender of that route throws and the whole build aborts.

## Fix (source environment — E1 to apply)
File: the payment callback page, `app/payment/callback/page.tsx` (or `.jsx`).

Move the `useSearchParams()` logic into a child component and wrap it in `<Suspense>`. Example:

```tsx
import { Suspense } from "react";
import { useSearchParams } from "next/navigation";

function PaymentCallbackContent() {
  const searchParams = useSearchParams();
  // ...existing callback logic that reads searchParams...
  return (/* existing JSX */);
}

export default function PaymentCallbackPage() {
  return (
    <Suspense fallback={<div>Loading…</div>}>
      <PaymentCallbackContent />
    </Suspense>
  );
}
```

Alternative (simpler, disables static prerender for this route): add to the top of the page file:
```tsx
export const dynamic = "force-dynamic";
```
The `<Suspense>` approach is preferred — it keeps the route optimizable and is the fix Next.js explicitly recommends.
